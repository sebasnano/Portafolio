Verificación

Problema

La cuenta del sistema dependía de un shell gestionado por Nix. Cuando el volumen correspondiente no estuvo disponible durante una recuperación, el login quedó acoplado a una capa que debía ser opcional.

Responsabilidad

Diagnostiqué la frontera entre cuenta del sistema, terminal y entorno declarativo; recuperé un login funcional y preparé una protección repetible sin aplicar cambios amplios sobre un árbol con trabajo no relacionado.

Restricciones

  • No reinstalar ni eliminar Nix para resolver un fallo de login.
  • No activar una generación completa mientras existiera trabajo no revisado.
  • Conservar Nushell como experiencia interactiva preferida.
  • Mantener una ruta de entrada basada únicamente en componentes nativos.

Arquitectura y enfoque

El inicio de sesión permanece en el shell nativo del sistema. La sesión interactiva inicia Nushell solo si su ejecutable gestionado existe y es ejecutable. Si esa condición falla, el shell nativo continúa como mecanismo operativo alternativo.

Decisiones y compromisos

  • Inicio de sesión nativo. Sacrifica la entrada directa a Nushell para garantizar recuperación independiente de Nix.
  • Arranque condicional. Conserva la experiencia diaria sin ocultar el mecanismo alternativo.
  • Terminal sin ruta rígida. Evita que la configuración de la aplicación vuelva a saltarse la frontera segura.

Implementación

Se corrigió el shell de cuenta, se retiró la ejecución directa desde la terminal y se preparó una comprobación declarativa que valida los marcadores de seguridad. Una variable de entorno permite abrir zsh explícitamente para diagnóstico.

Incidentes y aprendizajes

La declaratividad no debe eliminar la capacidad de recuperación del sistema base. Un componente administrado puede ser confiable en operación normal y, aun así, ser una mala dependencia para el login.
